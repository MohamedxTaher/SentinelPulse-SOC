01 / Data Flow

From raw logs to actioned alerts

Every SOC follows the same fundamental loop: collect, detect, enrich, respond. Each stage below is a working module in this project — not a diagram abstraction.

01
Ingest & Parse
The log parser classifies every line as syslog, Apache access or SSH/PAM auth, and flags suspicious keywords for downstream correlation.
02
Detect & Correlate
YAML detection rules and a sliding-window brute force detector run against the parsed entries. Matches fire MITRE-tagged alerts.
03
Enrich
Source IPs are checked against AbuseIPDB. A 97% abuse confidence score turns a suspicious login into a confirmed known-bad actor.
04
Respond
The NIST-aligned playbook gives analysts exact containment and escalation steps per alert type — triage to post-incident report.

04 / Incident Response

The response lifecycle

Based on NIST SP 800-61. Steps are decided in advance so nobody is improvising under pressure — the wrong action in the wrong order can turn a contained incident into a full breach.

1
Triage
Alert fires. First question: real threat or false positive? Check the source IP, timing and context before acting.
Target — within 5 minutes
2
Contain
Stop the spread. Block the source IP, isolate affected systems. Goal: deny the attacker any further movement.
HIGH alerts — within 30 minutes
3
Investigate & Eradicate
Build the event timeline from logs. Did any attempt succeed? Remove persistence, close compromised accounts, patch the exploited flaw.
Duration depends on complexity
4
Recover
Bring systems back online, verify clean state, monitor for recurrence.
With continuous monitoring
5
Post-Incident Report
What happened, what worked, what failed. Update detection rules so next time the catch comes earlier.
Within 5 business days
05 / Threat Intelligence

Context changes everything

When an IP shows up in your logs, knowing whether it is a known hostile source determines whether you monitor or block. Try the lookup — the demo uses the same data shape AbuseIPDB returns.

AbuseIPDB reputation lookup — demo dataset
Abuse confidence score
0–100 from AbuseIPDB. Above 80 is almost certainly malicious, based on community reports from security teams worldwide.
Geolocation & ISP
Where the attack originates and who owns the range. A Tor exit node or bulletproof host changes the escalation calculus.
Abuse categories
SSH brute force, port scan, web attack, spam. What the IP is known for predicts what it will try on your systems next.
